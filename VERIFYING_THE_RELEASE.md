# Verifying the English publication derivative

## Original formal computation

The supplied frozen package passed its original package validator with checksum verification. Its original strict formal-result validator also passed: 98 samples, ten outer repetitions, five outer folds, 58,800 OOF rows, 200 selection records, 18,000 representation-screening records, and 152,400 valid inner tuning records. All four components were included and all selected fits had resolved convergence.

## Publication transformations

Python comments and docstrings were removed without changing scientific executable ASTs. The importer and independent-sample test refer to English raw-workbook filenames, column headers, and worksheet names. The obsolete independent-sample test assertion expecting 9.24 for one protein value was corrected to 9.20, the value present in both the supplied laboratory workbook and the frozen model input. This is a test correction, not a chemical-data correction.

English raw workbooks preserve all 98 identifiers, numerical cell values, and row order. The source XLS reference workbook is represented as XLSX. The prepared chemistry and spectra and all frozen result tables remain byte-identical. The three PNG files supplied in the figure folders are byte-identical to the authoritative embedded images extracted from the author-revised manuscript. Figure source-data workbooks and executable plotting logic remain numerically unchanged. All three figure programs were executed successfully from temporary copies: their calculation assertions passed and each exported PNG, PDF, and SVG. The public package validator, independent-sample regression test, and twenty-family algorithm self-test also passed.

## Hash interpretation

Removing a comment changes a file hash. Therefore, the historical receipt in `v13_2_results/00_audit/formal_run_freeze_receipt.json` retains the original code hashes. It has not been re-signed to claim that the stored results were newly generated by these edited source files. The original frozen code/data hash inventories are retained in `provenance/Original_Code_Freeze_Hashes.json` and `provenance/Original_Data_Freeze_Hashes.json`.

`provenance/Publication_Transformation.json` connects original files to English derivative files using original hashes, current hashes, and executable-AST comparisons. The root `FROZEN_CODE_HASHES_V13_1.json` and `experimental_data/FROZEN_DATA_HASHES.json` describe the current public derivative for future runs. `SHA256SUMS.txt` covers every delivered release file except itself. Run `python verify_repository.py` to verify this combination, including historical receipt binding, without pretending that original and derivative code have identical bytes.

The unchanged original strict formal-result validator will reject `--formal` against a comment-stripped derivative because its original code hashes correctly differ. Use the release verifier for the supplied historical results. A newly generated rerun uses a new derivative-code freeze receipt and may be checked with the strict validator in its working copy.

## Verification scope

The release checks confirm the integrity and reproducibility of the supplied computations. They do not provide independent external validation, laboratory repeatability data, verified field/batch identifiers, a confirmed reporting basis, a nitrogen-to-protein conversion factor, or an endorsement of public-data redistribution rights. The complete expensive formal model search has not been repeated during this packaging step. Figure programs are checked independently of full model training.
